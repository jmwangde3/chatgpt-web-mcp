# Local 模式：每轮最新证据协作规范

## 1. 确认范围与分享许可

只读取当前项目/明确授权的文件；不扫描浏览器 Profile、凭据目录、个人数据或其他无关工作区。用户未允许将相关源码发给 ChatGPT Web 时，不发送证据。禁止 `git push`、自动建仓、自动发私有文件。对用户指定“本地模式、不上传 GitHub”，仍需确认具体是否允许把必要证据发给 ChatGPT Web；这两个外发范围不同。

## 2. 本轮证据取材

先找项目 `AGENTS.md`、相关源码和测试。仅采集：变更文件、直接调用方/被调用方、配置及状态数据结构、测试、上轮未解决问题的代码。工具示例（按当前环境有无 Git 灵活选用）：

```powershell
git status --porcelain=v1 -uall
git diff -- <本轮文件>
git diff --cached -- <本轮文件>
rg -n '<符号名>' <相关目录>
git rev-parse HEAD
```

无 Git 仓库时直接阅读已授权文件的最新内容、行号及哈希，记录手动比较基线或指出无 Diff 可提供。**不要因 Git 不存在而失败**。计算文件哈希可以使用 `Get-FileHash -Algorithm SHA256 -LiteralPath <路径>`；只发送核准的代码片段和必要上下文，绝不原样粘贴敏感测试输出。不需要建立永久 Context Packet 或仓库全量摘要。

## 3. 每轮最小证据包

```text
Mode: local
Evidence ID: <本轮唯一标识>
Workspace: <不含私有用户信息的项目标识>
Files: <相对路径 + SHA-256/版本 + 最新行号范围>
Diff: <仅相关代码本轮实际 Diff；无 Git 则说明方式>
Related calls/config/tests: <必要上下游代码与关键约束>
Tests: <实际命令、退出码、精简结果>
Unresolved findings: <ID/状态>

请仅根据本轮附带的源码与测试审查，按共享协议逐项给出证据、触发条件、后果和最小修法。列出实际读取/未读取的证据和缺口；证据不足请标记 NEEDS_EVIDENCE，不得假定你能访问我的本地磁盘。
```

如果证据过长，将**已授权**的必要文件分批送入同一 ChatGPT 会话，逐批记录覆盖范围；每批有新请求编号，等待前批完成；不要漏掉决定结论所需的函数及调用路径。不要将大量原始文件永久写入项目目录，临时产物按任务范围处理。

## 4. 下一轮与验收

Codex 处理建议后先重新运行对应测试，再从磁盘重读变化文件、Diff 与行号。未变化证据可复用前先比对哈希；哈希变化则重新读取。每轮重列 `Evidence ID`、文件清单、测试和问题状态。ChatGPT 不能证实本地代码已更新，只有 Codex 读回的真实文件/哈希可确定版本。默认最多两轮自动审查；按共享协议判 PASS / CONDITIONAL / FAIL，缺少本地证据则标 `INCOMPLETE`。

MCP 任务超时或控制异常只按 `$web-chat` 当前说明取回同一个 `task_id`；原发送结果不确定时停止自动重试，不换 `request_id`。不得凭旧网页答复声称本轮复审完成。
